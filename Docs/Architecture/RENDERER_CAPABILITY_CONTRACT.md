# Renderer Capability And Qualification Contract

**Status:** Required design contract
**Date:** 2026-07-14

## Purpose

The renderer targets multiple vendors, adapters, operating systems, and API implementations through `Engine::RHI` and NVRHI. Platform names are not capability checks. This contract defines how adapters are selected, which features are enabled, how fallbacks remain functional, and what evidence is required before a roadmap item claims backend/device coverage.

## Capability Terms

Keep these states distinct:

- **Advertised:** the adapter/API reports a feature, extension, format, or limit.
- **Enabled:** device creation explicitly enabled the feature when required.
- **Implemented:** Engine/RHI/renderer code has a path that uses it correctly.
- **Exercised:** a focused runtime test ran that path on the named device/backend.
- **Qualified:** representative workloads, captures, performance, and failure/fallback behavior meet the roadmap wording.

An advertised extension is not an enabled or qualified renderer feature. Logs and UI must not collapse these states into one “supported” flag.

## Current Bootstrap Foundation

The current implementation provides a backend-neutral capability lifecycle and pure profile evaluator. Synthetic EngineTests cover lifecycle invariants, required API/queue/presentation/format/limit rejection, explicit graphics-queue fallbacks, invalid preferred-adapter fallback, strict preferred-adapter failure, format-usage validation, and deterministic candidate tie-breaking.

Before native device creation, D3D12 and Vulkan now enumerate all visible adapters into the shared model and apply versioned Phase 3 Bootstrap profiles. The profiles gate minimum API level, maximum 2D texture dimension, graphics/presentation, timeline/fence synchronization, compatible compute/copy execution, `RGBA8_UNORM` sampled/color/copy use as required by the backend profile, and `D32_FLOAT` depth attachment use. Every candidate evaluation and selected fallback is retained in `DeviceCapabilities`, not only printed. Adapter identity includes a DXGI LUID or Vulkan device UUID so equal display names remain distinguishable on multi-GPU systems.

The selected devices publish conservative Bootstrap reports with adapter identity, queue mapping, queried formats, feature lifecycle state, qualification, and fallback diagnostics. D3D12 reports timestamps enabled/implemented only when the selected graphics queue exposes a nonzero frequency and the complete private RHI heap/resolve/readback/retirement path exists. Vulkan does so only with nonzero graphics-family `timestampValidBits`, positive physical-device `timestampPeriod`, and its complete private query-pool/record/non-waiting-readback/retirement path. D3D12 heap-direct indexing and enhanced barriers are disabled because the Bootstrap profile has no implemented consumer. Vulkan records buffer-device-address advertisement separately and leaves it disabled for the same reason. Optional ray, mesh, work-graph, and neural paths are not presented as usable renderer features merely because NVRHI advertises support.

The active Bootstrap report is copied into a renderer-owned read-only snapshot and presented in the editor Profiler. The diagnostics keep profile, adapter identity, qualification, queue/format decisions, feature lifecycle stages, selected fallbacks, every retained candidate rejection, and versioned consumer groups visible without leaking native or NVRHI types into the editor. D3D12 presentation support is necessarily finalized by real HWND swapchain creation after device selection; the pre-device profile can prove a direct queue but DXGI has no Vulkan-style per-surface physical-device query.

The first consumer group is `Phase3FrameTimingV1`. Device timestamp usability and renderer timing-consumer readiness are separate gates: P2B/P2C make both native RHI features usable, P3A associates raw endpoints with exact whole-frame/RenderGraph-pass identities, and P3B now publishes real asynchronous named-pass and whole-frame durations. The group begins each backend initialization on portable CPU steady-clock timing and promotes to exercised `GpuTimestamps` only after a real ready exact-frame publication. A diagnostic rendered before that publication may still show the CPU fallback; the publication marker and subsequent capability snapshot are authoritative for promotion. Unsupported devices, pending/disjoint results, and results whose exact renderer frame has already been evicted retain CPU/unavailable behavior rather than being relabeled or attached to the current frame. This does not complete benchmark headroom, Scene qualification, later consumer groups, physical-device breadth, or Production qualification.

GPU timestamp implementation is an explicit prerequisite for production frame-pacing selection and Phase 3E lighting/shading, not a late diagnostics-only enhancement. Before a pacing comparison may claim GPU headroom—and before Forward+/clustered lighting, PBR, lights, shadows, or sky/atmosphere begins—the shared RHI must allocate and record timestamp scopes, resolve them without a per-frame CPU stall, preserve frame/pass identity through readback, and publish valid whole-frame plus named-pass GPU durations. D3D12 uses timestamp query heaps; Vulkan uses timestamp query pools with timestamp-period/valid-bit handling and truthful unsupported/disjoint results. RenderGraph pass labels are the profiling scope authority. Pacing artifacts may derive target-budget headroom only from a valid duration associated with the same frame ID. CPU steady-clock timing remains a functional fallback on devices without usable timestamps, but that fallback cannot qualify a claim about GPU cost or headroom.

Native per-pass GPU timestamp capture is not a permanent live-editor tax. It is enabled automatically by the RenderGraph timing smoke and frame-pacing benchmark, or explicitly for an ordinary run with `--renderer-gpu-timestamps`; otherwise the live Profiler retains CPU cadence/work evidence and reports GPU pass timing unavailable. `--renderer-disable-gpu-timestamps` is a diagnostic override for isolating capture overhead and must not be used by evidence that claims GPU duration or headroom. Lightweight CPU stage summaries require the separate `--renderer-frame-trace` opt-in. This policy preserves the implemented GPU timing path while preventing D3D12 Debug query-resource retirement from distorting the cadence being inspected.

Delivery is split at real authority boundaries. P1 establishes the backend-neutral query-pool lifecycle and deterministic failure/reuse semantics without claiming native execution. P2A1 adds logical-validation-before-callback, exact-token publication, and bounded post-submit native-state retirement. P2A2 retains the logical pool through public-wrapper destruction before submit and adds non-mutating publication preflight. P2B is locally qualified on D3D12 through private heaps/readback/frequency. P2C is locally qualified on Vulkan through a private pool, the live NVRHI command buffer, valid-bit masking, physical period, and non-waiting exact-token collection. NVRHI's paired timer-query API is not substituted for the indexed P1 contract; raw calls remain inside RHI escape hatches and reuse the NVRHI-created device/queues/commands. `GetTimestampPeriodNanoseconds` gives P3 one portable scale.

P2D is the production asynchronous-lifetime boundary exposed before P3. Both viewport renderer implementations submit their valid-Scene light-payload-copy/primary-directional-shadow/clear/raster/tone-map/output-handoff RenderGraph. `SubmittedRenderGraphFrameOwner` retains up to four heap-owned graphs, authoritative frame IDs, accepted-prefix pass labels, all accepted exact tokens, and shared payloads for pass-captured resources that live outside the graph, including D3D12 mapped frame-slot constants, Vulkan per-frame constant buffers, tone-map constants, the primary-directional shadow frame/map/pipelines, and the immutable Scene-light payload with its staging and GPU buffers. It polls without waiting and releases a frame only when every token is complete. Same-queue final Graphics handoff preserves ordering into native presentation; any cross-queue producer remains governed by compiled dependencies. Pending constant-slot or light-payload-slot reuse, Vulkan output replacement, capacity exhaustion, duplicate identity, and invalid/failed completion are explicit failures rather than hidden waits or dropped work. Device idle is used only at shutdown before final owner release. P2D adds no timestamp measurement. P3 consumes this owner to associate query generations with frame/pass identity and publish Profiler durations/headroom. A checked foundation never makes a later stage implicitly complete.

P3 is split at its three publication authorities. P3A records one independent two-query transaction per accepted effective-Graphics RenderGraph pass because a P1/P2 transaction belongs to one command list and exact submission token; separately submitted viewport passes cannot share one logical transaction. Scope order encloses graph-derived barriers/acquires, named pass work, and releases, while unsupported independent queues reject before recording. The current six-pass production graph adds Scene-light payload copy and primary-directional shadow depth ahead of clear/raster/tone-map/output handoff, so four retained frames permit 24 reserved or unresolved native query states. P2D owns each pool/generation until its exact token is terminal, then emits only raw frame/pass/token/generation endpoints; failed tokens remain retained but expose disjoint terminal observations rather than fabricated values. P3B validates exact frame/label/token/generation/period/Graphics-clock identity, converts each ready scope with the pool's nanoseconds-per-tick scale, publishes named-pass durations, and derives whole-frame time only as final-pass end minus first-pass start. It amends a bounded renderer history by exact frame ID, ignores a missing/evicted record as unavailable, exposes the latest completed result to Profiler, and promotes the capability only after ready native evidence. Summing pass durations, subtracting across queues, or attaching a late result to the current frame is forbidden. The native retirement queue serializes concurrent worker reservation/publication/retirement because graph pass recording is parallel. P3C independently retains benchmark frames and accepts an amendment only for the same retained frame ID; schema 3 publishes GPU status/duration and computes headroom only from that frame's positive effective Smooth target and ready interval. Schema 4 adds cadence/limiter source identity; schema 5 adds exact-source input-to-simulation/submit/Present engine intervals while input-to-display and click-to-photon remain unavailable. Responsive, missing-target, invalid, stale, evicted, pending, unavailable, and disjoint cases do not invent headroom. CPU fallback remains truthful; none of these slices supplies display or input-to-photon evidence.

`Phase3TransientResourcesV1` is the ordered capability prerequisite for graph transient allocation. It prefers `PlacedAliasedTransient` only when RHI reports both placed-resource and alias-barrier translation usable; otherwise it selects `NonAliasedGpuRetiredPool`. That fallback means committed or non-aliased pooled resources, with future cross-frame reuse gated only by RHI completion-token retirement. It does not mean CPU-frame-number reuse, and it does not relax graph lifetime compatibility. Current D3D12 and Vulkan/NVRHI reports select the fallback because neither translation exists in the backend-neutral RHI. The local RTX 3080 Ti headed smokes exercise selected-path diagnostics and presentation publication on both backends. This is not a native placement/alias-barrier claim, an allocator implementation, a memory-cost measurement, or hosted fallback-regression evidence.

The former single Vulkan scene checklist item is deliberately split into four ordered claims. First, an NVRHI-backed Vulkan `Engine::RHI::Device` core owns buffers, RGBA8/depth textures, clear, explicit transitions, command submission, uploads, staging readback, markers, and GPU-safe retirement, proven by deterministic offscreen clear/readback after the existing context creates its one native device and queue. Second, SPIR-V consumption, reflected binding/input layout, graphics pipeline/framebuffer state, constant update, and indexed offscreen draw/readback use that core. Third, the `NVRHIVulkanViewportSceneRenderer` acquires the published immutable `SceneRenderSnapshot`, applies the shared camera-relative raster preparation and `EditorViewport.hlsl` SPIR-V package, and records only `Engine::RHI` commands into its RGBA8/depth outputs. Fourth, the real editor viewport exports only the completed NVRHI-owned image/view to the existing native Vulkan ImGui bridge. The output finishes in shader-read-only layout; Presentation owns descriptor/sampler registration/removal, waits for GPU retirement before output replacement, and owns WSI/ImGui submission. `VulkanSceneOutputCaptureV1` distinguishes output production from `VulkanSceneOutputHandoffV1`, which requires descriptor registration, Editor `ImGui::Image` queuing, and successful post-resize swapchain presentation. The adapter creates neither a second `VkDevice` nor raw Vulkan Scene commands; raw Vulkan remains bootstrap/WSI/ImGui-only. This is Presentation-plus-current-Scene-output evidence on the named device class, not broad production-device qualification.

## Vulkan Queue Admission

Vulkan exposes Compute/Copy only when logical-device creation returned a selected concrete handle; otherwise each resolves truthfully to Graphics. Local Windows RTX 3080 Ti qualification selected Graphics family 0/index 0, Copy family 1/index 0, and Compute family 2/index 0. Hosted Vulkan jobs are fallback/regression evidence unless their logs show the admitted topology.

## Adapter Selection

The engine must enumerate adapters and select by required capabilities, limits, presentation support, and user preference rather than vendor identity. Selection must record:

- backend/API and API version;
- adapter name, vendor/device identifiers, type, and driver/runtime version when available;
- required capabilities that passed;
- optional capabilities that were enabled or rejected;
- selected queue families/classes and presentation support;
- selected format and resource-limit decisions;
- the reason a candidate was rejected or a fallback backend/device was selected.

A strict backend request fails clearly if its minimum contract is not met. An ordinary launch may use a documented fallback selected before native device creation. The reported active backend must match the device actually running.

The selected device also publishes `MaximumReadOnlyTextureTableCapacity`, including reserved error slot zero. Vulkan derives it from the minimum of the selected physical device's per-stage and descriptor-set sampler/sampled-image limits and the engine ceiling. D3D12 derives it from the engine ceiling and the shader-visible sampler-heap limit. Shader defines, reflected array counts, logical table allocation, native layout realization, and Scene cache capacity must all use this one value. A logical table request above the selected adapter limit fails before native layout creation; a portable fallback must never compile a 4096-element interface merely because a different adapter supports it.

Use `--renderer-adapter=<exact name or stable ID>` (or the split-value form) to prefer a device. A missing or unqualified preference falls back to the best qualified device and records the reason. Add `--renderer-adapter-strict` to reject every nonmatching device and terminate initialization instead of falling back. Stable IDs are the unambiguous choice when multiple devices expose the same display name; they are runtime identifiers, not content or save-file identifiers.

## Required Capability Groups

The capability report grows with roadmap phases. Before a consumer is implemented, its required group must exist in `Engine::RHI` and have a deterministic fallback or an explicit unsupported result. Open-ended “all future groups” checkboxes are not completion gates: each versioned group belongs immediately before its real roadmap consumer and carries its own implemented, exercised, and qualification state.

| Consumer | Capability group |
| --- | --- |
| Phase 3 frame timing | Prefer usable GPU timestamps; portable CPU steady-clock frame/pass timing is the functional fallback. Group qualification remains separate from device qualification. |
| Phase 3 scene renderer | Resource formats/usages, sampled/storage/attachment support, queue submission/synchronization, shader target/reflection compatibility, descriptors/samplers, timestamps when timing is claimed. |
| Phase 3 transient resources | Heap placement/aliasing and alias barriers when available, plus a correct non-aliased committed/pooled fallback and GPU-retired reuse. |
| Phase 4 image quality | Sample counts, multisampled attachment/storage behavior, alpha-to-coverage, sample-rate interpolation where used, anisotropy, sampler LOD behavior, resolve formats. |
| Phase 6 visibility/material resolve | `R32_UINT` attachment/storage support, fragment barycentrics or a functional reconstruction alternative, descriptor indexing/material-table limits, subgroup behavior, indirect dispatch/draw capabilities, compact G-buffer formats. |
| Phase 7 virtual geometry | Indirect draw count or bounded fallback, buffer device address only if the implementation needs it, vertex layout/stride limits, subgroup/culling support, optional mesh shaders with indexed-indirect fallback. |
| Phase 8 probes/volumetrics | 3D images, view compatibility needed by the chosen froxel/volume layout, compressed/HDR formats, sampling/storage limits. |
| Phase 9 ray residuals | Acceleration structures, ray tracing/ray queries, shader binding/table requirements, update/compaction support, queue/build limits, and a raster/probe fallback when unavailable. |

Do not enable every advertised feature. Enable only features required by the selected renderer profile and optional paths that have an implemented, exercised consumer.

## Shader Portability

The shared shader contract uses Slang/HLSL-style authoring and produces validated per-stage packages for the current D3D12 and Vulkan Scene viewports. The admitted target set is host-specific and exact: Windows x86_64 with pinned Slang v2026.13.1 plus pinned DXC v1.9.2602 produces paired DXIL+SPIR-V; Linux and macOS with their staged Slang package produce SPIR-V-only. A Linux/macOS DXIL request fails before compilation with an explicit unavailable-target diagnostic: no non-Windows DXC package or system compiler is admitted. The D3D12 RHI consumes the Windows package's DXIL; the NVRHI-backed Vulkan Scene path consumes the same validated SPIR-V package for reflected binding/input layout, graphics pipeline creation, constant updates, indexed draws, and immutable-snapshot viewport raster. Convention schema 2 retains logical D3D register/space reflection while Slang maps Vulkan binding classes to non-overlapping physical offsets `b=0,t=100,u=200,s=300`; this mapping is cache-keyed and NVRHI layouts must use the same offsets. Normal runtime requests use asynchronous job-system fire-and-poll with atomic last-valid-package publication; deterministic-inline execution exists for focused smoke tests. Version-2 disk packages and the in-process completed-package cache use canonical SHA-256 keys over source identity/content, entry/stage, compiler identity/version and admitted package hashes, exact ordered targets, sorted defines/options/dependencies, layout/reflection versions, expected interface, and convention schema.

The implemented contract requires:

- deterministic output for every requested, admitted host target (paired DXIL+SPIR-V on Windows x86_64; SPIR-V-only on Linux/macOS);
- reflected resource layouts matched against C++ structures and RHI pipeline layouts;
- explicit coordinate, depth, clip-space, matrix-layout, and binding conventions;
- cache keys that include source, compiler, target, defines, and layout version;
- diagnostics that identify source, entry point, target, and backend;
- focused rendering through every backend claimed to consume a target.

The Windows x86_64/MSVC D3D12 viewport and its DXIL consumption are exercised. The Vulkan RHI graphics path consumes the package's SPIR-V in both deterministic indexed offscreen draw and immutable-Scene-snapshot raster paths; native ImGui-output integration remains separate. Linux/macOS hosted tests compile, reflect, convention-validate, cache, diagnose, and execute a real SPIR-V-only Scene raster package rather than skipping shader compilation. MinGW Scene raster, Windows ARM64, broader physical-device classes, and production qualification remain unqualified until their matching runtime evidence is recorded; redistribution remains blocked pending the exact binary-component/notice audit recorded in [DEPENDENCIES.md](../DEPENDENCIES.md). Live source-change pipeline rebuild is also separate and remains pending.

The current portable vertex-layout capability is deliberately narrower than the future Phase 7 geometry-stream group: one interleaved slot-zero, per-vertex stream with an explicit pipeline stride and `R32G32Float`/`R32G32B32Float` attributes. Empty-input pipelines use zero stride. Nonempty zero stride, offset-width overflow, attributes extending past the stride, other formats, other slots, and instance rates reject before native layout creation. A bound vertex buffer must publish the same stride before a draw can consume it. This makes the existing 32-byte vertex and the planned 44-byte position/color/UV/normal vertex portable without claiming multiple streams, packed formats, instancing, or device-specific stride/alignment qualification.

NVRHI's Vulkan graphics implementation requires Vulkan 1.3 dynamic rendering and synchronization2. The Vulkan profile queries, rejects when absent, enables, and reports both before device creation. NVRHI's binding layouts follow convention schema 2: constant buffers use offset 0, shader resources 100, unordered access 200, and samplers 300, preserving HLSL register spaces as Vulkan descriptor sets without cross-class collisions.

## Descriptor And Binding Model

The renderer must define capacities, update/retirement rules, error descriptors, and non-bindless fallback behavior for:

- sampled textures and samplers;
- read-only structured/geometry buffers;
- explicit writable resources;
- per-frame material, instance, light, and draw-cluster tables.

Descriptor indexing/bindless use is capability-gated. If a device cannot support the selected table shape, it must choose a documented bounded-table/batched path or report the renderer profile unavailable. Streaming updates and descriptor reuse must be GPU-retired; CPU frame number alone is insufficient.

The first Phase 3D prerequisite is deliberately only a backend-neutral logical sampled-texture table. It declares one mandatory exact-device-owned retained error texture at slot zero, accepts capacity only in `[2, kMaximumReadOnlyTextureTableCapacity]`, uses deterministic lowest-free allocation with generation identities, and accepts only valid logical sampler enums plus textures carrying `ShaderResource` without `RenderTarget`, `DepthStencil`, or `UnorderedAccess` usage. Slots, pending replacements, and resolved views retain `Ref<Texture>` ownership. Invalid/stale identities resolve to that error identity; foreign, null, writable, invalid-sampler, or invalid-capacity inputs fail without publication. Replacement and removal retain the old and replacement identities until the exact submitted `CompletionToken` retires with `Complete` or `Failed`; no CPU-frame-number reuse is permitted. The `DescriptorIndexing` capability selects the logical bindless path only when usable, otherwise the same declared capacity selects the bounded read-only path. Current NVRHI D3D12/Vulkan adapters report descriptor indexing unavailable because this prerequisite creates no native descriptor heap/set, sampler object, shader binding, or table upload. In particular, the current Scene viewport color/depth outputs are writable renderer targets and cannot enter this table. Texture upload, material resolution, native descriptor realization, and Scene-format qualification remain later work.

The portable shader-facing declaration permits exactly one sampled texture table at `t0,space1` with its matching sampler table at `s0,space1`; Vulkan uses physical offsets 100 and 300, while the current per-draw constant buffer remains `b0,space0`/offset 0. A declaration colliding with any declared constant-buffer space or changing those fixed logical/physical locations is invalid. `CommandList::BindGraphicsSampledTextureTable` rejects unless an active pipeline carries that declaration and the table belongs to the exact device; setting another pipeline clears the binding.

The first structured-buffer consumer is intentionally narrower than the eventual material/light/draw tables: one optional pixel-stage read-only `StructuredBuffer<uint4>` at `t0,space3`, with a fixed 16-byte element stride and count one in reflection. Pipeline creation validates the exact register, space, stage, resource kind, type shape, count, and stride before native layout creation. `CommandList::BindGraphicsReadOnlyStructuredBuffer` accepts only an exact-device, GPU-only buffer with exactly `BufferUsage::Structured` plus optional `CopySource`/`CopyDest`, stride 16, and a nonzero size divisible by 16. Every bind attempt first invalidates the active binding, every pipeline change invalidates it again, and a draw whose active pipeline declares the resource fails unless a valid buffer was rebound. Earlier successful bindings and their native objects remain retained for the whole recording even when a later bind becomes active or fails. D3D12 realizes this as a root SRV so the existing sampled-table heaps remain installed; Vulkan realizes it as the convention-preserving set-3 structured-buffer SRV. This fixed binding is not a general SRV table, descriptor indexing, arbitrary register/space support, writable storage, host-visible binding, or a capability claim for future structured layouts.

That fixed binding's first production consumer is the versioned Scene-light payload. Renderer validates one immutable snapshot view and its matching CPU clustered grid before packing complete typed light records plus global-directional and CSR local-index tables. Four publication slots pair CPU-write staging with GPU-only structured storage; the production graph copies and transitions the selected slot before Raster, and the submitted-frame owner retains the immutable payload and both buffers through all accepted exact tokens. Both renderer sources bind the same interface while production `PSMain` preserves neutral preview lighting. Linux/Vulkan exact diagnostic readback is qualified; directional/point/spot evaluation, D3D12 execution, MoltenVK execution, general structured descriptors, and a GPU-built cluster grid remain separate.

The functional bounded fallback is now realized without claiming descriptor indexing. Each bind snapshots only `TextureBindingTable::ResolvePublishedSlot`, so queued replacement/removal remains invisible until exact-token retirement. D3D12 builds command-list-owned shader-visible SRV and sampler heaps, installs root tables, maps all four logical point/linear clamp/wrap samplers, and retains the referenced textures through submission. Vulkan builds the fixed arrays as an NVRHI set-1 binding layout/set at physical bindings 100/300, maps the same samplers, and retains the set, samplers, and textures through submission. Capacity must match reflected arrays exactly and slot zero remains the error resource. `DescriptorIndexing` stays unavailable because this is a fixed-capacity fallback; true bindless indexing, material/artifact integration, mips, streaming, and residency require later consumers and evidence.

The ordered content prerequisite before that native realization is a single RHI-owned full-subresource initializer. It accepts only exact-device-owned, non-writable 2D RGBA8 UNORM/sRGB textures with one mip/layer/sample and `CopyDest|ShaderResource`; exact source format/extent, at-least-tight row pitch, and exact byte count are required. D3D12 performs the private footprint upload and final `ShaderResource` transition in one Graphics submission because a Copy queue cannot record that shader-read transition; Vulkan/NVRHI performs `writeTexture` on Graphics followed by the same portable state. The existing completion-token wait is the publication authority, so no source/staging lifetime is released before native acceptance. It supplies no descriptor, sampler, shader-visible binding, mip, streaming, or residency claim.

The fixed sampled-table declaration carries one capacity in `[2, 4096]`, including error slot zero. Portable reflection reports one `t0,space1` texture array and one `s0,space1` sampler array with that compile-time count; pipeline creation rejects zero/out-of-range capacity and missing or mismatched arrays, while binding rejects another table capacity. Native qualification uses a capacity-two table and a real slot-1 sampled-output/readback oracle on both local backends. This still does not enable `DescriptorIndexing`.

The former combined texture-upload/sampler/mip line is a large exit gate split into five ordered mechanisms in `PLAN.md`. T1 is the portable boundary: only a validated canonical `TextureArtifact` may become a `TextureArtifactUploadPlan`. The plan owns an immutable payload copy, preserves asset/source provenance plus role, color space, target profile, and alpha metadata, maps the cooked format without reinterpretation to RGBA8, BC5, BC7, or ASTC 4x4, and derives every row pitch and byte range from the RHI format's block layout. Planning failure is transactional. T1 does not query device support, choose a different artifact, allocate or upload a native texture, publish a sampled-table slot, generate a mip, or establish GPU retirement.

T2A converts that plan to one immutable `TextureUploadBatch` only when every authored mip appears once in ascending order, has the exact halved extent and block-aware range, ends at or before the legal 1x1 level, and covers the payload exactly. The selector consults only the selected device's retained `FormatCapability` table for `Sampled|CopyDestination`; missing entries are unsupported. It may choose a separately cooked RGBA plan only when asset/source, role, color space, alpha, base extent, and mip count match, and it publishes a visible fallback diagnostic. A mutable format relabel, missing capability record, or mismatched fallback fails without replacing the caller's prior selection.

Native T2 upload is a whole-resource synchronous initializer. D3D12 queries one copy footprint per mip, copies each block row through a private upload buffer, transitions all subresources to `ShaderResource` on Graphics, and retains staging through the exact completion wait. Vulkan creates the declared mip count and issues one NVRHI `writeTexture` per mip before the same whole-resource transition and exact completion wait. Exact-device probes now retain RGBA8/sRGB plus BC5/BC7/sRGB usage records; ASTC remains absent because the admitted NVRHI format enum has no ASTC representation, so the selector must take the explicit RGBA fallback. Whole-resource state tracking accepts a nonempty single-layer/single-sample mip chain, while cross-queue texture ownership transfer deliberately remains single-mip until its own range contract is accepted. T3 owns role/color-space-correct completion of genuinely missing mips. T4 owns resolver/cache/table publication and exact retirement. T5 owns real material and sampler consumption; Phase 4 remains authority for anisotropy and broader sampler-LOD quality.

T3 is an Assets/import policy, not a renderer or runtime-GPU generator. `PreserveAuthored` validates and retains any legal authored prefix without adding levels. `CompleteMissing` retains every supplied level byte-for-byte and appends only the absent suffix through 1x1 before `CookNormalizedRgba8` publishes the artifact. Base-color and emissive RGB use the fixed IEC 61966-2-1 sRGB-to-UNORM16 table and nearest inverse code, while alpha stays linear. Normal RGB decodes to signed vectors, averages the complete source footprint, and uses deterministic integer-square-root renormalization with neutral `(128,128,255)` for a zero vector; alpha remains linear. ORM and mask channels use rounded integer-linear averages. Proportional integer source bounds include all texels for odd and single-axis extents instead of dropping the final row or column. Invalid roles, color spaces, payloads, policies, or levels beyond the legal 1x1 bound fail without replacing caller output. A complete normalized chain is never filtered, and an incomplete compressed KTX2/Basis chain requesting `CompleteMissing` fails visibly with instructions to provide a complete authored chain or normalized RGBA8 source; the importer does not decode and re-encode a canonical compressed artifact.

T4 is split because catalog publication, native upload/cache publication, and GPU-retired table mutation have different authorities. Accepted T4A atomically publishes mesh and texture resolvers backed by one copied Assets registry generation at every existing Editor publication point; resolution acquires that immutable catalog, preserves caller output on failure, has no device or table side effect, and the catalog is cleared through the same lifecycle operation called by Renderer shutdown. Its Linux Debug build, exact mesh/texture resolver tests, style, and diff gates passed. Accepted T4B selects the preferred artifact or only its matching separately cooked RGBA fallback against the exact device, creates and synchronously uploads the selected complete mip chain, requires the resource to reach `ShaderResource`, and only then publishes a Ref-owned immutable bundle. Its collision-free value identity covers the device instance, normalized provenance, preserved semantics, complete RHI description, mip ranges, and every payload byte. Exact hits reuse the bundle; changes publish a new monotonic generation; deterministic eviction and explicit clear release only cache ownership; selection, creation, upload, or post-upload-state failure leaves both the caller's output and accepted entries unchanged. Cache and external bundles must be released before device destruction. The deterministic adversarial test and real RTX 3080 Ti Vulkan probe qualify this boundary without allocating a sampled-table slot or changing a material; D3D12 execution of the required matching marker remains part of the next hosted integration batch. Accepted T4C owns the logical table and maps stable asset/sampler views only from valid exact-device T4B bundles. Compatible views share the immutable resource while retaining distinct handles and exact last-use state. It records bound bundles for accepted frames in submission-acceptance order, selects the latest accepted use for replacement/removal of each view, freezes that view's new resolution to the error handle while its old slot stays visible to accepted work, and retains old/new bundles plus the logical operation until that exact token is `Complete` or `Failed`. Only then does update become visible or removal advance the generation for reuse. Invalid bundle, handle, token, capacity, and premature-retirement paths do not mutate accepted publication. Accepted T4V closes the persistence boundary exposed by parent feasibility: the former single derived artifact path let a later target cook replace the prior target, whereas target-qualified DesktopBC, ASTC, and RGBA-fallback paths now coexist under one stable source handle. Explicit target resolution validates the recorded target and registry provenance; variant-set resolution returns one preferred artifact plus an optional semantically matching RGBA fallback from the same immutable catalog generation. Missing optional fallback succeeds visibly, while a present corrupt/mismatched variant and a missing preferred target preserve caller output. Legacy unsuffixed artifacts can satisfy only the target recorded inside them.

Accepted parent T4 composes those boundaries in `TextureRuntimePublication`. One resolver snapshot generation selects and uploads the bundle, then maps it to a stable `(texture asset, sampler)` table view; compatible views share the immutable cache bundle/resource while retaining distinct generation-safe handles and last-use state. A catalog refresh freezes new resolution only for the affected view while its latest-use operation is pending, commits immediately if that exact use was already terminal, and synchronously replaces/removes a view that never entered accepted GPU work. Content replacement preserves the view's sampler. Every failure stays on the declared error resource. Both native Scene renderers own this coordinator under device-idle lifecycle, and the Linux RTX 3080 Ti marker exercises the complete catalog/cache/table/retirement chain, including simultaneous `LinearWrap` and `PointClamp` views over one resource and exact-token replacement/removal of both. Matching native D3D12 execution remains pending. T5 now owns material lookup and shader-visible Scene consumption; T4 does not infer material meaning from filenames or silently bind another asset.

Accepted T5A adds material values to the same copied publication generation rather than exposing Editor's mutable `MaterialLibrary` to render threads. Lookup requires matching `AssetType::Material` registry metadata and library content from that one snapshot and is transactional on every failure. All current Editor registry/material mutation boundaries publish the pair together.

Accepted T5S makes sampler intent part of that immutable material value. Material schema 2 carries one of the existing four portable point/linear clamp/wrap modes for every texture slot; schema 1 migrates to `LinearWrap`, and invalid or incomplete schema-2 declarations never replace caller state. The Editor republishes live selector changes through T5A. This is an Assets/Editor declaration only: T5 still owns slot-role validation, mapping to the RHI table sampler, texture resolution, constants/table binding, and shader-visible behavior on both Scene paths.

Accepted Linux/Vulkan T5B is the first real material Scene consumer. `TextureRuntimePublication` resolves one immutable material and all declared texture artifacts from the same catalog generation, validates BaseColor/Emissive as sRGB and Normal/ORM/Mask roles as linear, maps each persisted sampler to its RHI table view, and leaves undeclared slots on shader semantic defaults while declared invalid slots use the visible error resource. Both Scene renderer implementations publish identical material factors, six table indices, declaration/error masks, alpha mode, and shading model to `EditorViewport.hlsl`; the default project persists a deterministic 64x64 seven-mip sRGB artifact on its prototype material. Accepted raster submissions retain the exact sampled bundles until the raster token is terminal. Vulkan additionally caches the fixed 4096-entry native binding set by table identity/revision, creates at most the four distinct native sampler states for one realization, and reuses persistently mapped constant buffers through the existing four-frame ownership bound. This removes the measured per-frame descriptor/sampler rebuild and synchronous constant upload without changing D3D12's current native table implementation. The T5 parent remains open for executed D3D12 qualification and exact shader readback that distinguishes every auxiliary semantic and mip choice.

Accepted Linux/Vulkan T5C supplies the exact shader-readback half of that parent gate. The shared shader's acceptance entry uses the production material constant/table ABI and explicitly samples both BaseColor mip levels plus every auxiliary semantic. A complete, empty, and semantically invalid immutable material distinguish correct sRGB/linear formats, four declared sampler modes, shared-resource/different-view identity, semantic defaults, and the error texture in exact RGBA8 cells. One real RHI submission retains the sampled handles and retires their exact token. The same marker is mandatory in Vulkan and D3D12 harnesses; only Vulkan execution is claimed until the Windows platform run passes.

## Fallback Rules

- Optional mesh shading falls back to compute culling plus indirect indexed draws.
- Unsupported fixed sampler mip bias uses explicit LOD/gradients or another verified filter path.
- Unsupported sample-rate interpolation selects a coverage/AA path that does not require it.
- Unsupported ray tracing preserves the stable raster/probe renderer and marks ray residuals unavailable.
- Missing compressed formats select an engine-cooked fallback format without changing texture semantics.
- Missing async/secondary queues run on a compatible queue with correct synchronization; performance may change, correctness may not.

Fallbacks must be visible in diagnostics and exercised. Silently disabling a feature while leaving its UI or backend report enabled is a failure.

## Qualification Levels

| Level | Evidence | Valid claim |
| --- | --- | --- |
| Build | Project generation and compilation. | Builds for named toolchain/platform. |
| Bootstrap | Instance/device/NVRHI creation and capability log. | Device initializes. |
| Presentation | Native ImGui/swapchain present plus resize/post-resize present. | Editor presentation works. |
| Scene | Representative Engine::RHI resources, shaders, commands, and capture. | Scene renderer works on named backend/device. |
| Production | Representative content, performance/profiling, packaging, clean-machine launch, and fallback/error coverage. | Production renderer qualified for named platform/device class. |

Roadmap wording must name the achieved level and device class. Hosted software/virtual devices do not imply physical hardware qualification.
