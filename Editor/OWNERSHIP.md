# Editor Ownership

The editor is a client of the engine. It owns panels, workflows, inspectors, viewports, guided creation, and AI-assisted tooling.

The editor may ask engine diagnostics APIs for renderer and asset data, but it must not reach around public engine boundaries to mutate private runtime state.

The opt-in control mailbox is Editor-owned verification tooling. Its accepted schema 3 retains fixed material inspect and select-plus-surface-patch actions plus fixed entity inspect/select, complete Transform, typed Light, complete project color-pipeline, and dedicated main-camera viewport-pose actions. It additionally admits only two bounded debug-workflow actions: complete Scene-debug view/selected-bounds publication bound to the expected selected entity, and complete MeshRenderer visibility/shadow-flag mutation bound to stable entity identity. The shared foundation puts document mutations through normal Scene or MaterialLibrary validation and Editor history/restore, while debug state uses the normal immutable Renderer publication and generation authority. Mailbox work executes on the Editor main thread through normal renderer-publication, selection/pivot/camera, and history authorities and publishes bounded terminal receipts with at most 32 sampled affected stable IDs. Every mutation is explicitly session-only/not-saved. It must not become arbitrary dispatch, a network service, implicit save authority, entity/component lifecycle authority beyond the fixed outliner actions admitted under "Control Mailbox: Editor UI Actions" below, or a substitute for the future model-neutral Automation boundary.

## Fab Browser Module (`Editor/src/Fab`)

`Editor/src/Fab` is the Editor-private home of the integrated Fab browser panel described by `Docs/Architecture/FAB_ASSET_INTEGRATION.md` (2026-10-09 amendment). Engine and Sandbox never include it, and no browser-engine header (CEF or any other) may appear anywhere outside the Editor's adapter files and the separate browser-helper executable.

The directory is split by dependency, and the split is a contract:

- **Pure core** (`BrowserSurface.h`/`.cpp`, `BrowserFrameMirror`, `BrowserNavigationPolicy`, `BrowserSignInHosts` (the user-granted sign-in host book, its versioned file codec, and the consent banner state machine), `BrowserDownloadPolicy`, `BrowserInputRouter`, `FabIntake`, `NullBrowserSurface`): standard C++ and `Engine/Core/Base.h` plus the `Engine/Platform/ExternalUrl.h` URL primitive only. No CEF, ImGui, GLFW, RHI, or other native-graphics include is allowed in these files, and they hold no engine thread or global state. Every `IBrowserSurface::Listener` callback is delivered on the main thread from inside `Pump()`. These files are also compiled into `EngineTests` (see `Tests/premake5.lua`) and exercised through `Tests/src/TestSupport/FakeBrowserSurface.h`; adding a file to this tier means adding it to that list, and nothing that needs a browser engine, ImGui, GLFW, or a GPU may be added to it.
- **Adapters** (the future engine-backed `IBrowserSurface`, the ImGui panel, and the helper executable): the only code allowed to include third-party browser or UI headers. They consume the pure core and are not compiled into `EngineTests`.

Authority stays where the Fab contract puts it. The navigation policy composes `Engine::IsAllowedExternalHttpsUrl` rather than re-implementing URL grammar. The panel never reads the browser profile, cookies, or the download URL; a staged download is handed to the Engine-owned import authority as a path, and `FabIntake` is a routing classifier whose results the Engine snapshot and ZIP authorities re-validate. The panel is an acquisition adapter, not a second importer.

## Project Manifest And Browser Helper

The project manifest codec is no longer Editor code: `EditorLayer` reads and writes the manifest through thin wrappers over `Engine::ProjectManifest` (format 7). The Editor owns when to commit and the undo barrier, never the commit mechanism. `Editor/helper/` builds `SpiralBrowserHelper`, the separate browser subprocess executable (built only when `Vendor/CEF` is present); it is staged under the Editor's `cef/` directory, and no other Editor, Engine, Sandbox, or test target links or includes CEF.

## Fab Import Controller And CEF Host Library

`Editor/src/Fab/FabImportController.*` is the headless import state machine: it includes Engine headers only (no ImGui, GLFW, CEF, or RHI), is compiled into `EngineTests`, and never touches live Editor state; the Editor adopts a committed result. `Editor/src/Fab/CefBrowserSurface.cpp` is the only CEF-including adapter and is compiled solely into `libSpiralBrowserHost.so` (`Editor/browserhost/`), which the Editor must load with `dlopen` and never link; `SpiralBrowserSmoke` drives it headlessly through the same factory. The Editor, Engine, Sandbox, and `EngineTests` targets never include or link CEF.

## Editor Module Structure

`Docs/Architecture/EDITOR_UI_ARCHITECTURE.md` (2026-10-09) fixes the target layout of `Editor/src`. The existing `Fab/` directory and `EditorMaterialControl.*` keep their locations and owners. New code uses the `SpiralEditor` namespace. `EditorLayer.{h,cpp}` becomes the composition root: it owns the session, history, command registry, panel registry, and layout manager and forwards attach, update, UI, and event hooks; it carries no panel or smoke bodies.

| Directory | Tier | Owns | Forbidden |
| --- | --- | --- | --- |
| `Core/` | pure, in `EngineTests` | `EditorSession` document model, `SelectionModel`, `HierarchyModel` (rows, filter, naming policy, protections), `LogBuffer`, notification/status model, `UiScale` arithmetic | ImGui, GLFW, CEF, RHI, native graphics, threads, globals, any other Editor directory |
| `Commands/` | pure, in `EngineTests` | `CommandRegistry` and typed argument variants, `ShortcutMap`/`ResolveShortcut`, fuzzy matching | the same, and `History/`, `Layout/`, `Panels/`, `Viewport/` |
| `History/` | pure, in `EngineTests` | `HistoryStore<State>`, `HistoryLabel`, `EditGestureTracker`, the size-estimator interface | the same; it must not know `Scene`, `AssetRegistry`, or `MaterialLibrary` (the state type is a template parameter, and capturing and restoring the real state stays in the composition root) |
| `Layout/` | pure codec in `EngineTests`; `LayoutManager` is the single ImGui adapter file | schema-versioned workspace/layout codec, panel visibility and detach-policy tables | ImGui in the codec files |
| `Gizmo/` | pure in `EngineTests` except `GizmoDraw.cpp` | `GizmoVec`, `GizmoMath`, `SnapMath`, `TransformGizmo` state machine, Euler recomposition | ImGui and `Panels/` in the pure files; the sector-local snapping logic consumes `Engine::Math` and does not reimplement world-grid normalization |
| `Panels/` | adapter (not in `EngineTests`), except the pure `PanelDescriptor` header | `IEditorPanel`, `PanelRegistry`, `PanelHost`, one file per panel, status bar, toast layer, command palette, shortcuts and preferences windows | including `EditorLayer.h`, including another panel, calling `ImGui::Begin` outside `PanelHost` for a registered panel |
| `Viewport/` | adapter plus pure helpers | `ViewportNavigation` (behavior unchanged from the DESIGN.md contract), toolbar, overlays, view modes, `ViewportToolState`, the absolute-to-viewport-relative coordinate helper | native-graphics access beyond the documented UI/presentation bridges |
| `Smoke/` | Editor-only | the `Run*Smoke` and control-smoke definitions moved out of `EditorLayer.cpp` | reachability from any pure-tier file |

A file added to a pure tier is added to the `EngineTests` list in `Tests/premake5.lua` in the same change, and the dependency rules above are enforced by review and, because `EngineTests` has no ImGui, GLFW, CEF, or RHI include path of its own, by the pure-tier build itself (a forbidden include fails to compile there; the slice that adds the first pure directory confirms this against `Tests/premake5.lua`). Panels receive a narrow `PanelContext` of references, never `EditorLayer*`. The command registry is the only place action logic lives: menus, context menus, toolbars, shortcuts, the command palette, panel detach and dock, workspaces, and typed control actions call `Execute`, and none contains its own copy. Editor-owned persistent files (layouts, `Editor Preferences`, viewport tool state) are workspace-global, schema-versioned, atomically written, fail closed to defaults, and never part of `.spiralproject`.

## Main-Window-Only Panels

The **Scene Viewport** and the **Fab browser panel** are pinned to the main OS window in v1 and must not be hosted by a secondary OS window by drag, saved layout, or typed `DetachPanel`. Their input comes from main-window `Engine::Event`s and window-relative cursor coordinates (the viewport also uses main-window cursor capture), and engine callbacks are never chained for secondary windows. Every other docked panel may be detached on Linux/Vulkan/X11 once the multi-viewport slice is accepted; detaching is visibly disabled on Direct3D 12, native Wayland, OpenGL2, and when the surface offers neither MAILBOX nor IMMEDIATE. The Editor never enables ImGui viewports itself: the Engine UI layer owns the enablement guard.

## Control Mailbox: Editor UI Actions

The mailbox remains opt-in, Editor-owned verification tooling. After the in-flight Fab schema 4 lands, the next schema versions admit exactly the fixed named actions listed in `Docs/Architecture/EDITOR_UI_ARCHITECTURE.md` and nothing else: `InspectHistory`, `UndoHistory`, `RedoHistory`, `SetTransformToolState`, `ApplyGizmoOperation`, the outliner lifecycle actions `CreateEntity`, `DuplicateEntities`, `DeleteEntities`, `RenameEntity`, `SetSelection`, `SetEntityLock` (group 1), and `ListViewports`, `DetachPanel`, `DockPanel` (group 2, after multi-viewport). Each maps to exactly one registered command with typed arguments, runs the same validation and history path as the UI on the Editor main thread, uses complete-value compare-and-swap preconditions and exact field masks, records history with `Source = Agent`, publishes a bounded terminal receipt (64 KiB, at most 32 sampled affected stable IDs), and is explicitly session-only and not saved. The mailbox never accepts a command-id string, arbitrary dispatch, add/remove-component or asset-assignment lifecycle beyond what its existing fixed actions cover, a network endpoint, or save authority. Adding any further UI action requires amending the architecture contract first.
